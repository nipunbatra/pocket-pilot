What changed after training?

With the original native checkpoint, correct lane choices were 28/216 for JSON and 81/216 for images. The fine-tuned native models each reached 216/216. The browser exports below also retained all 216 correct lane choices at every question count.

The model's original decision head is trained alongside LoRA updates to its language layers. The image model receives actual pixels and a constant text context. No obstacle coordinates, target lane, or corrected answer enters that image request. It reads images; it does not generate images.

How to identify the loaded model

The model selector explicitly says fine-tuned JSON, fine-tuned image, or original · not fine-tuned. The input selector is locked to the matching modality for each fine-tune. Timing + metadata records the exact Hugging Face revision and whether the weights are fine-tuned. Switching models releases the previous model from memory.

Limits and reproducibility

Train/calibration/test: 540/108/216 synthetic road scenes with disjoint barrier-height bands. Three epochs; checkpoint selected by calibration loss. These results concern this road and question wording, not general-purpose reasoning or vision. Classroom mode pauses while the model answers; real-time driving may still collide if an answer is wrong or late.

The browser uses q8 decision weights, a shared unchanged q4 embedding table and fp16 vision encoder. JSON and image fine-tunes are separate checkpoints. Native RTX A2000 medians for one question were 9.5 ms (JSON) and 31.7 ms (image); those are not browser timings.
