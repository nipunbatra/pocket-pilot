04 / Three small contracts

Choose the shape before asking.

choice A category

A supplied label, a distribution over labels, and a separate confidence value.

{ "choice": "left",
  "probabilities": { "left": 0.99, "middle": 0.01, "right": 0 },
  "confidence": 0.99 }

noul A probability

1 means an estimated 100% probability of “yes”. It is numeric, not a boolean.

{ "noul": 1 }

score An ordered scale

A probability-weighted average of the level indices; fractional values are valid.

0 × 0.1 + 1 × 0.3 + 2 × 0.6 = 1.5Illustrative distribution. Our recorded frame returned score 0.

A probability or confidence of 1 is still a model estimate. It does not prove the prediction is correct.

The first two snippets are excerpts of the recorded answer. The score arithmetic is deliberately labelled illustrative so students see why the value can be fractional. A score of 1.5 is not a 150% danger probability. Noul has no separate confidence field.

05 / From an answer to a use

Three types. Three different jobs.

Pick an option, judge a claim, or place something on a scale.

choice

Pick one option.

“Which lane is open?”

"left"

The selected label from left / middle / right.

What our code does

Sets the car’s target lane to left. The probabilities let us compare the alternatives.

Use for categories: choose a lane, a route, or a label.

noul

Judge a yes/no claim.

“Is the middle lane blocked?”

0.8

An estimated 80% chance of yes; 20% of no.

What our code does

Displays the probability. To turn it into an action, your code would choose a threshold.

Use when the question is “Is this true?” Keep uncertainty visible.

score

Place it on a scale.

“Where is the barrier?”

1.5

Between middle (1) and bottom (2) on our ordered scale.

What our code does

Tracks the barrier’s estimated position as it approaches. This is not metres or seconds.

Use for ordered levels: position, severity, or quality.

Illustrative answers. In this game, only choice steers; noul and score describe the frame.

Ask students which type they would use for “Which lane?”, “Is it blocked?”, and “How far down the image?”. Choice names an option; left and right are not numbers to average. Its probabilities compare the supplied alternatives, while confidence is a separate model-reported estimate, not a guarantee. Noul 0.8 is a probability, not the boolean true; a hypothetical application threshold of 0.7 would classify it as yes, while 0.9 would not. This game does not threshold noul to steer. Score 1.5 summarizes a distribution over the supplied level indices. It does not say the barrier is physically halfway between two positions, and different distributions can have the same average. Reopen the probability distribution when the distinction matters. All values on this slide are illustrative.

06 / Why use this API?

A better fit for bounded decisions.

Our controller needs a lane label and uncertainty—not a paragraph.

What we needPlain text LLM callLLM + structured outputDecisions API
Machine-readable resultApplication must interpret the wordingJSON follows a supplied schemaBuilt-in typed answers
One of three lanesPrompt conventionCan constrain an enumchoice is a native question
UncertaintyUsually expressed in wordsA generated numeric field is possibleReturns distributions for choice / score
Best use hereExplain a driving strategyProduce a custom plan or objectRepeated small judgments on a frame

Why it helps: less output interpretation and an interface designed for fast, constrained judgments.

What we haven’t proved: that it is more accurate, better calibrated, cheaper, or faster than another model on this game. That needs a fair benchmark.

Source: OpenAI Decisions guide. Use Responses for explanations/custom schemas; function calling for tool requests.

Do not create a false dichotomy: structured outputs can already enforce an enum. Decisions’ useful contract here includes the distribution over alternatives and the small fixed question types. The official guide describes a speed advantage; we have not run a matched local benchmark, so do not present our live timings as proof of one.

09 / Close the loop
Receiving an answer is only half the job.


  1. Validate the shape.Check types, finite values, labels and probabilities.
  2. Check freshness.The result must belong to the current barrier and active run.
  3. Steer to the chosen lane.Finish each lane change. Recheck at the next image checkpoint.
  4. Keep the evidence.Record the input, response, timing and action outcome.

Pausing fixes the timing mismatch. It cannot fix an incorrect model prediction.


This is application design, not magic inside the endpoint. The current game freezes both motion and game time during requests in Classroom mode. The explicitly labelled Real time experiment lets the road continue. There is one in-flight request at a time. Only local diagnostics compare the chosen lane with the known gap.
